  Design Section 1: Data Model

  struct Student {
      char id[20];        // 学号 (primary key)
      char name[30];      // 姓名
      char gender[5];     // 性别
      char building[10];  // 宿舍楼号

  };

  struct DormSystem {
      Student* students;  // Dynamic array
      int count;          // Current number of records
      int capacity;       // Allocated capacity
  };

  - Dynamic array starts at capacity 100, grows by doubling when full
  - id serves as the unique key for all operations
  - Data persisted to data.txt as text (one record per line, fields separated by

⏺ Design Section 2: CRUD Module

  Add — Prompt user for all fields, validate ID uniqueness, append to array
  (grow if needed)
  Delete — Find by ID, confirm, shift array elements left to fill gap
  Modify — Find by ID, show current data, prompt for new values (empty = keep
  current)
  Display All — Print all records in a formatted table

  Key decisions:
  - All lookups by student ID (unique key)
  - Delete uses array compaction (shift elements)
  - Modify allows partial updates (press Enter to skip a field)

  Design Section 3: Search Module (3 algorithms)

  ┌──────────────────┬─────────────────────────────────────────┬────────────┐
  │    Algorithm     │                Use Case                 │ Complexity │
  ├──────────────────┼─────────────────────────────────────────┼────────────┤
  │ Sequential       │ Search by any field (name, room, major) │ O(n)       │
  │ Search           │                                         │            │
  ├──────────────────┼─────────────────────────────────────────┼────────────┤
  │ Binary Search    │ Search by student ID (requires sorted   │ O(log n)   │
  │                  │ array)                                  │            │
  ├──────────────────┼─────────────────────────────────────────┼────────────┤
  │ Block/Index      │ Search by building (block index on      │ O(√n)      │
  │ Search           │ building field)                         │            │
  └──────────────────┴─────────────────────────────────────────┴────────────┘

  - Sequential: general-purpose, works on any field
  - Binary: fast but requires sorting by ID first; the system will maintain a
  sorted-index array
  - Block: builds an index table on building number, then searches within the
  block

  Design Section 4: Sorting Module (3 algorithms)

  ┌────────────────┬────────────────────┬───────────────────────────────────┐
  │   Algorithm    │        Key         │               Notes               │
  ├────────────────┼────────────────────┼───────────────────────────────────┤
  │ Bubble Sort    │ By student ID      │ Simple, stable, for demonstration │
  ├────────────────┼────────────────────┼───────────────────────────────────┤
  │ Quick Sort     │ By name            │ Fast, recursive implementation    │
  ├────────────────┼────────────────────┼───────────────────────────────────┤
  │ Insertion Sort │ By building + room │ Good for nearly-sorted data       │
  └────────────────┴────────────────────┴───────────────────────────────────┘

  - Each sort can be applied to any field (user chooses sort key at runtime)
  - After sorting, binary search becomes available on the sorted field
  - All sorts operate on the same dynamic array (in-place)
